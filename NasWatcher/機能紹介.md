# NAS WATCH 機能紹介

イーサーネットから NAS を自動検出し、**1 ページ**で「接続・容量・速度・ホットスポット」をまとめて管理できる Windows デスクトップアプリです。

- **配布形態**: 単一 exe (`NasWatcher.exe` / 約 53 MB)。.NET ランタイムのインストールは不要
- **UI**: HTML + CSS + JavaScript (WebView2) / **バックエンド**: .NET 10 (C#)
- **必要環境**: Windows 10 2004 以降 / Windows 11、Microsoft Edge WebView2 Runtime

---

## 画面は 1 ページ・5 つのカード

| カード | ひとこと |
| --- | --- |
| **NAS 検出** | 有線LANのサブネットを走査して NAS 候補を一覧表示 |
| **SMB 接続先** | `\\IP\共有名` をコピペ用に表示 / コピ�� / エクスプローラーで開く |
| **NAS の容量** | 共有の空き容量を取得して使用率を表示 |
| **通信速度** | 受信・送信速度を 1 秒間隔でグラフ表示 |
| **モバイルホットスポット** | テザリングの ON/OFF と、モバイル端末からの接続支援 |

---

## 1. NAS 検出（有線LAN から IP アドレスを自動取得）

選択した有線LANアダプター (Windows の「以太网」) の IP とサブネットから、NAS の IP アドレスを自動で探します。

**検出の流れ**

1. **ARP テーブル** を読み、同サブネットのホストを候補に追加
2. **サブネットを並列スキャン**（最大 /24、254 ホスト × 7 ポートを同時処理）
3. 応答したポートから種類を判定

| ポート | 判定 |
| --- | --- |
| 445 | **NAS (SMB)** |
| 5000 / 5001 | NAS / Web (Synology DSM など) |
| 80 / 443 / 8080 | Web サーバー |
| 22 | SSH サーバー |

4. **逆引き DNS** でホスト名を取得（例: `LS710DF8C.local`）
5. `NetServerGetInfo` でサーバー情報を取得し、種別タグを表示

**表示例**

| IP アドレス | ホスト名 | 種別 | 応答 |
| --- | --- | --- | --- |
| 169.254.10.28 | LS710DF8C.local | `NAS (SMB)` | 408 ms |
| 169.254.169.232 | MetaQuest5 | `NAS (SMB)` | 440 ms |

> **追加 IP** 欄，输入已知的 IP アドレス（NAS 处于别的网段时）也可以直接扫描。

---

## 2. SMB 接続先（コピペできる IP アドレス）

检测结果を 1 行選ぶと、SMB パスが automatically 组成されます。

```
\\169.254.10.28\share
```

- **［コピー］** → そのままクリップボードへ（Windows エクスプローラーやコマンドプロンプトへ貼り付け可）
- **［SMB で開く］** → `explorer.exe \\IP` でエクスプローラーを起動
- **［Web で開く］** → 検出したポートから Web 管理画面を開く（既定ポート 80/443 はポート番号を省略）

共有名は自動列挙（`WNetOpenEnum` → 失敗時は `net view` の出力を解析）されます。
列挙できない場合は **共有名欄に直接入力** して［更新］を押せば取得できます。

---

## 3. NAS の容量（SMB / SNMP）

共有にアクセスして空き容量を取得し、使用率バーと数値を表示します。

```
使用済み 874.13 GB / 合計 7.24 TB          12%
169.254.10.28\share  使用率 12%  空き 6.39 TB  認証: 現在ログイン中のユーザー
```

**取得の順番**

1. **SMB** (`WNetAddConnection2` + `GetDiskFreeSpaceEx`)
   - 認証は設定した方式に加えて **「ゲスト (匿名)」「現在ログイン中のユーザー」** を自動で順に試します
   - 失敗時は Win32 エラーコードと原因・対処を表示します
2. **SNMP**（SMB で取得できなかった場合）
   - `HOST-RESOURCES-MIB` (`hrStorageSize` / `hrStorageUsed` / `hrStorageAllocationUnits`)
   - `UCD-SNMP-MIB` (`ucdavisTotalReal` / `ucdavisAvailReal`)
   - コミュニティ文字列とポートは設定タブで変更できます（既定: `public` / 161）

> NAS の管理画面で SNMP を有効にしておくと、SMB の認証.\\
> 関係なく容量が取得できます。

## 4. 通信速度（受信・送信）

各ネットワークアダプターを 1 秒間隔で計測し、Canvas に滑らかな曲線グラフを描画します。

- 受信 (水色) / 送信 (橙) を別で表示、���計 2 分分
- 対象アダプターは切替可能（既定は選択中の有線LAN）
- `NetworkInterface.GetIPv4Statistics()` の差分値を秒あたりに換算

---

## 5. モバイルホットスポット

Windows 標準のモバイルホットスポットを WinRT API (`NetworkOperatorTetheringManager`) で操作します。

- **スイッチひとつで ON / OFF**
- 状態 / SSID / パスフレーズ / 接続クライアント / ゲートウェイ IP を表示
- **パスフレーズは既定で伏せ字**（目アイコンで表示・非表示を切替）
- SSID とパスフレーズの変更にも対応

---

## 6. モバイル端末 (iPhone 等) から NAS へ接続する

NAS が **リンクローカル (169.254.x.x)** にある場合、モバイル端末から直接は到達できません。
NAS 側���インターネット経由の返信経路がないため、応答が NAS に戻らず
「ソケットが接続されていない」状態になります。

NAS WATCH はこのケースのために **2 つの手段** を用意しています。

### (1) 接続テスト / 接続可否の診断

モバイル端末と同じ経路 (ICS の NAT 相当) で NAS に接続し、結果を详细に表示します。

- 成功 / タイムアウト / 接続拒否 / 到達不能 を区別
- 問題がある場合は原因と対処を提示

### (2) TCP リレー / HTTP プロキシ（PC が中継）

PC が中継 (中継サーバー) になるため、NAS 側の返信経路が無くてもモバイル端末からアクセスできます。

- **Web (80 / 5000 / 5001 / 5005 / 5006)** → HTTP プロキシ
  - `Location` ヘッダーを中継元のアドレスへ書き換え
  - NAS が HTTPS へリダイレクトする場合は代理側で取得して内容を返す
  - HTML の `<base>` タグを挿入し、相対リンクが壊れないようにする
- **SMB (445) / HTTPS (443)** → RAW 中継

**待受ポートの決め方**

- 基本は **転送先と同じポート** (NAS の Web が 80 なら待受も 80)
- そのポートが使えない場合は自動で空きポートへ切り替え、使用したポートを画面に表示
- SMB (445) の場合、Windows 自身が 445 を使うため、**Windows の SMB サーバーを一時停止**して
  確実に確保します (リレー停止時に自動で元に戻します)

**iPhone の「ファイル」アプリから使う場合**

| 方法 | 手順 |
| --- | --- |
| **WebDAV** (推奨) | NAS 側で WebDAV を有効化 → アプリのリレー欄で「WebDAV (5005)」を選択 → iPhone の「ファイル」→「接続先サーバーに追加」→ `http://192.168.137.1:5005` |
| **SMB** | アプリのリレー欄で「SMB (445)」を選択 → iPhone の「ファイル」→「接続先サーバーに追加」→ `smb://192.168.137.1` |

> iOS の「ファイル」アプリは SMB のポートが 445 固定のため、NAS 側で WebDAV が使える場合は
> WebDAV 経由のほうが確実です。

> **［LAN アクセスを許可］** ボタンで、モバイル端末からの受信を許可する
> ファイアウォール規則を追加できます（管理者権限が必要です）。

## 設定

「設定」ボタンから変更できます（`%APPDATA%\NasWatcher\settings.json` に保存）。

| 項目 | 内容 |
| --- | --- |
| NAS の IP アドレス | 既定の接続先 |
| 共有名 | 既定の共有 |
| Web 管理画面のポート | 既定 5000 |
| SMB 認証方式 | 現在ユーザー / ゲスト / ユーザー名とパスワード |
| ユーザー名・パスワード | SMB 認証情報 |
| 資格情報を Windows に保存 | Windows 資格情報マネージャーに保存 |
| ポート検出の待ち時間 | スキャン時のタイムアウト (既定 400 ms) |
| SNMP コミュニティ文字列 | 既定 `public` |
| SNMP ポート | 既定 161 |
| SMB で取得できないときは SNMP で取得 | ON / OFF |
| 起動時に自動スキャン | ON / OFF |

---

## トラブルシューティング

| 症状 | 対処 |
| --- | --- |
| 容量が取得できない | 設定タブの認証方式を「ユーザー名とパスワードを指定」にして入力。共有名を直接入力して［更新］も試す |
| NAS が見つからない | 有線LANアダプターが IP を持つことを確認。別セグメントなら「追加 IP」に入力 |
| iPhone から接続できない | モバイルホットスポットのカードの「接続テスト」を実行。必要なら「LAN アクセスを許可」でファイアウォール規則を追加 |
| 共有一覧が空 | 認証設定を確認。手動で共有名を入力して［更新］ |
| SNMP が取れない | NAS の SNMP 機能とコミュニティ文字列を確認 |

---

## 開発

```bash
dotnet build -c Release        # ビルド
dotnet run -c Release          # 実行
dotnet publish -c Release -o publish   # 単一 exe の生成
```

### 構成

```
NasWatcher/
├─ Program.cs                 エントリポイント
├─ app.manifest               DPI / バージョン情報
├─ Core/
│  ├─ AppSettings.cs          設定の永続化
│  ├─ AppLog.cs               ログ
│  ├─ Format.cs               バイト数・速度の整形
│  ├─ NetworkAdapters.cs      NIC 列挙 / サブネット計算
│  ├─ HostDiscovery.cs        NAS 探索 (ARP + ポートプローブ)
│  ├─ SmbClient.cs            SMB 共有列挙 / 空き容量
│  ├─ SmbErrors.cs            Win32 エラー / サーバー情報
│  ├─ SnmpClient.cs           SNMP (v1/v2c) クライアント
│  ├─ SpeedMonitor.cs         通信速度の計測
│  ├─ HotspotService.cs       モバイルホットスポット (WinRT)
│  ├─ LanAccessHelper.cs     モバイル端末からの接続診断 / ファイアウォール設定
│  ├─ TcpRelay.cs             RAW TCP 中継
│  └─ HttpProxy.cs            HTTP プロキシ (Location / base タグ書き換え)
├─ UI/
│  ├─ MainForm.cs             WebView2 ホスト
│  ├─ AppBridge.cs            C# ⇄ JSON ブリッジ
│  └─ assets/                 UI (exe に埋め込み)
│     ├─ index.html
│     ├─ styles.css
│     └─ app.js
└─ 機能紹介.md                このドキュメント
```

UI とバックエンドは JSON で Bridge します
(`window.chrome.webview.postMessage` ↔ `CoreWebView2.PostWebMessageAsJson`)。
UI ファイルは exe に埋め込まれており、起動時に `%LOCALAPPDATA%\NasWatcher\ui` へ展開されます。
